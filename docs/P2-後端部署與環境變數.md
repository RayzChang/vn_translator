# P2 後端部署與環境變數

## 環境變數（Vercel 或本機）

在 Vercel 專案 **Settings → Environment Variables** 新增：

| 變數 | 說明 | 範例 |
|------|------|------|
| `DATABASE_URL` | PostgreSQL 連線字串 | `postgres://user:pass@host:5432/dbname?sslmode=require` |
| `ENCRYPTION_KEY` | 加密 API 金鑰用，至少 16 字元 | 隨機長字串（建議 32 字元） |
| `JWT_SECRET` | 簽署登入 token 用 | 隨機長字串（建議 32 字元） |

- **DATABASE_URL**：可用 [Vercel Postgres](https://vercel.com/storage/postgres)、[Neon](https://neon.tech)、[Supabase](https://supabase.com) 等提供的 Postgres，建立後複製連線字串即可。
- **ENCRYPTION_KEY**、**JWT_SECRET**：可用 `openssl rand -hex 32` 或任意長字串，勿與他人共用或提交到程式庫。

## 資料庫初始化

後端第一次處理註冊或登入時會自動執行 `CREATE TABLE IF NOT EXISTS`（見 `api/lib/db.ts` 的 `initDb()`），因此**不必手動建表**。若你希望手動建表，可在 Postgres 執行：

```sql
CREATE TABLE IF NOT EXISTS users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  login_id VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS settings (
  user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  api_key_encrypted TEXT,
  model_id VARCHAR(100) DEFAULT 'gemini-2.5-flash',
  preferences JSONB DEFAULT '{}',
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 本機測試（含 API）

1. 設定環境變數：在專案根目錄建立 `.env`（勿提交），內容例如：
   ```
   DATABASE_URL=postgres://...
   ENCRYPTION_KEY=你的32字元密鑰
   JWT_SECRET=你的JWT密鑰
   ```
2. 安裝 Vercel CLI：`npm i -g vercel`
3. 執行：`vercel dev`  
   - 會同時啟動前端與 `/api` 後端，瀏覽器開提示的網址（例如 http://localhost:3000）即可測試登入、註冊與翻譯同步。

## 僅前端本機（不含 API）

執行 `npm run dev`，只會跑 Vite 前端；呼叫 `/api` 會 404，**登入／同步無法使用**，但未登入時仍可用本機 API 金鑰翻譯。

## 部署到 Vercel

1. 將專案推送到 GitHub，在 Vercel 匯入該 repo。
2. 在 Vercel 專案設定中新增上述三個環境變數。
3. 部署後，前端與 `https://你的網域/api/*` 會一併上線；同一帳號在多裝置登入即可同步設定與金鑰。
